# AI 工具介紹手冊網站化：階段執行計劃書

> 文件日期：2026-08-26  
> 計劃期間：2026-09-01 ～ 2026-10-02  
> 目標：將目前的章節 HTML prototype 與內容規格，轉為可維護、可公開瀏覽，並可部署至 Cloudflare Pages 的正式手冊網站。

## 1. 專案現況與執行原則

### 現況

- 已有 Part 1～4 的內容規格書與 10 份獨立 HTML prototype。
- 各頁已有視覺化方法圖解、提示詞摺疊與複製功能。
- 尚未有統一入口頁、共用元件、內容資料結構、建置流程或部署設定。

### 第一版目標

完成一個公開的靜態內容網站，讓讀者可以：

- 從首頁理解手冊用途與整體學習路徑。
- 在一致的章節版型中閱讀 Part 1～4。
- 展開並複製提示詞、使用前後章導覽，並在手機上順暢閱讀。
- 透過 Cloudflare Pages 的預覽部署校稿，確認後發布至正式網址。

### 技術方向

- 網站框架：Astro。
- 內容格式：MDX；每一章為一份內容檔，並以 frontmatter 管理章節資訊。
- 部署：Cloudflare Pages + GitHub Git integration。
- 第一版不包含：帳號系統、資料庫、CMS、留言／表單後端、AI 即時生成服務。

## 3. 階段工作計劃

### 階段 0：啟動與內容盤點

**日期：2026-09-01 ～ 2026-09-02**

**工作項目**

1. 以 `handbook_content_revision_spec-9.md` 為內容真實來源，列出各章節標題、摘要、方法、提示詞、延伸資源與建議產出。
2. 確定網站網址結構，例如：

   ```text
   /                         首頁
   /handbook/                手冊總覽
   /handbook/1-1/            1.1 先找到想處理的問題
   /handbook/2-2/            2.2 建立 PRD 初稿
   /methods/                 方法工具庫
   /resources/               延伸資源
   ```

3. 從現有 prototype 擷取共用視覺規則：色彩、字級、留白、卡片、標籤、提示詞區塊與流程圖風格。
4. 建立「內容遷移對照表」，明確標記每個 prototype 已遷移、待校對或待補圖的內容。

**產出**

- 網站地圖。
- URL 規格。
- 共用元件與內容欄位清單。
- 章節遷移清單。

**驗收標準**

- 所有 10 份 prototype 都有對應的正式網站頁面與 URL。
- 不將規格書中的「討論紀錄／待確認事項」直接當成讀者正文。

### 階段 1：建立網站骨架與共用元件

**日期：2026-09-03 ～ 2026-09-09**

**工作項目**

1. 初始化 Astro 專案，建立開發、建置與預覽命令。
2. 建立網站基礎版型：首頁、手冊頁、方法頁、延伸資源頁、404 頁。
3. 製作可重用元件：

   - `ChapterHeader`：章號、標題、摘要、閱讀資訊。
   - `WhyHowWhat`：WHY／HOW／WHAT 區段。
   - `MethodCard`：方法名稱、說明、例子與圖解容器。
   - `PromptBlock`：提示詞展開／收合與複製按鈕。
   - `ChapterNavigation`：上一章、下一章與回到總覽。
   - `Sidebar`：Part 導覽與目前章節狀態。

4. 建立全站設計 token 與 RWD 斷點，避免沿用每頁各自內嵌的 CSS。
5. 製作首頁：手冊目的、四個 Part、完整流程與開始閱讀 CTA。

**產出**

- 可本機執行的網站骨架。
- 首頁、手冊總覽與一份示範章節頁。
- 共用元件與樣式系統。

**驗收標準**

- 桌面與手機寬度下，導覽與文章均可閱讀。
- 提示詞複製、摺疊區塊與前後章導覽可正常運作。
- 網站內容不再依賴各頁內嵌重複 CSS／JavaScript。

### 階段 2：內容遷移與閱讀體驗完成

**日期：2026-09-10 ～ 2026-09-18**

**工作項目**

1. 依序將 Part 1、Part 2、Part 3、Part 4 改寫為 MDX 內容頁。
2. 將每章統一整理為：章節摘要、WHY、方法、提示詞、建議產出、延伸資源。
3. 將現有 CSS 示意圖改為共用圖解元件；不適合共用的圖示，保留在章節專用樣式中。
4. 補齊文章 metadata：標題、描述、Part、章序、前後章與閱讀時間。
5. 建立方法工具庫與延伸資源頁，集中顯示所有框架與外部連結。
6. 導入靜態搜尋（例如 Pagefind），讓讀者能搜尋方法、工具與提示詞關鍵字。
7. 逐一檢查外部 AI Skill／GitHub 連結的可用性與描述正確性。

**產出**

- Part 1～4 全部正式頁面。
- 方法工具庫、延伸資源頁與靜態搜尋。
- 完整的章節導覽與前後文關係。

**驗收標準**

- 10 個 prototype 對應內容均已遷移，且可從首頁到達。
- 每章均可複製提示詞、前往相鄰章節並回到手冊總覽。
- 搜尋可找到章節標題與主要方法名稱。

### 階段 3：上線品質與內容校對

**日期：2026-09-21 ～ 2026-09-25**

**工作項目**

1. 進行桌面、平板、手機的版面與互動測試。
2. 執行無障礙校對：標題階層、鍵盤操作、按鈕標籤、色彩對比與焦點樣式。
3. 補齊 SEO：每頁 title／description、canonical、Open Graph、`sitemap.xml`、`robots.txt`。
4. 檢查所有外部連結、複製功能、404 頁與站內導覽。
5. 檢查正式文本與規格書的一致性，避免遺漏已確認內容或將內部討論帶入公開頁。
6. 建立上線版的截圖與基本測試紀錄。

**產出**

- 上線檢查清單與測試紀錄。
- 可部署的正式建置產物。

**驗收標準**

- 無失效的站內連結，外部連結皆經檢查。
- 手機版的文字、表格與方法圖解不會水平溢出。
- 正式頁面具有正確 metadata 與 sitemap。

### 階段 4：Cloudflare Pages 部署與發佈

**日期：2026-09-28 ～ 2026-10-02**

**工作項目**

1. 將程式碼推送至 GitHub，建立 `main`（正式）與功能分支的協作規則。
2. 在 Cloudflare Pages 建立 Git-integrated 專案：

   - Production branch：`main`
   - Build command：`npm run build`
   - Build output directory：`dist`

3. 確認每一個 Pull Request 有預覽網址，並以預覽站完成內容校稿。
4. 先發布 `*.pages.dev` 網址，進行最終驗收。
5. 若已有網域，設定自訂網域、HTTPS 與正式站重新導向策略。
6. 撰寫部署與回滾說明：發現問題時，透過還原 Git commit 或重新部署前一版處理。

**產出**

- Cloudflare Pages 正式專案。
- Preview 部署流程。
- `*.pages.dev` 測試網址與正式自訂網域（如適用）。
- 部署／回滾操作說明。

**驗收標準**

- `main` 分支更新後能自動部署至正式站。
- 功能分支或 Pull Request 有獨立預覽網址，且不影響正式站。
- 正式網站可由預定網址正常瀏覽，HTTPS 正常生效。

## 5. 風險與控制方式

| 風險 | 影響 | 控制方式 |
| --- | --- | --- |
| 原型與規格內容不一致 | 上線文字錯誤或遺漏 | 以規格書為唯一內容來源，維護遷移對照表 |
| 各章圖解差異過大 | 共用元件難抽、維護成本升高 | 先抽卡片與排版骨架，特殊圖解保留章節專用樣式 |
| 內容遷移耗時超出預期 | 影響上線日期 | 先完成首頁、Part 1 與完整導覽，後續 Part 可分批發布 |
| 直接上正式站才校稿 | 改錯風險高 | 所有變更先在 Cloudflare Preview URL 驗收 |
| 過早加入後端功能 | 增加成本與維護負擔 | 第一版維持純靜態網站，驗證需求後才導入 Workers／資料庫 |
