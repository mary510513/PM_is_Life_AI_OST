1.2 理解使用者與情境

跟 1.1 的差異：1.1 是先猜出問題可能是什麼，1.2 是去確認這個猜測對不對。
WHY 為什麼要理解使用者與情境
  • 1.1 整理出來的問題，還只是我們的猜測。
  • 這一步要做的是：找真實使用者聊聊、觀察看看，看猜測有沒有猜對。
  • 猜對了，後面的方向才會準；猜錯了，現在發現比之後發現便宜多了。
HOW 可以嘗試的 5 個方法
Empathy Map 從使用者的所說、所想、所做、所感切入
Says 說「路線沒問題，都看導航」
Thinks 想擔心遲到被扣分
Does 做常常自己改道，不走建議路線
Feels 感對系統的路線建議沒有信任感
例：外送員「說」路線沒問題，但「做」的時候常常自己改道，不走 App 建議路線。
User Journey Map 把使用者的完整體驗按時間排出來
🙂
接單
😐
前往店家
😣
等店家出餐
🙂
送餐完成
例：「等店家出餐」是整趟旅程中外送員最容易感到煩躁的階段。
Persona 把資料收斂成一個具體的人
陳
小陳・兼職外送員
背景：白天上班，下班後接單
目標：多接單、少繞路
痛點：最怕遇到出餐慢又難停車的店家
例：「小陳」是兼職外送員，下班後接單，最怕遇到出餐慢又難停車的店家。
使用者訪談 直接問使用者本人
你平常送餐時，遇到出餐慢會怎麼處理？
通常會先去接下一單，晚點再回來拿
那你怎麼決定要不要先去接下一單？
例：訪談時要問行為，不要問「你會不會用」這種假設性問題。
觀察法 看使用者實際怎麼做，不只聽他說
👁️
說：都看 App 導航 → 觀察到：常憑記憶抄捷徑
例：外送員說自己都看 App 導航，但觀察發現他其實常常憑記憶抄捷徑。
WHAT 提示詞範例（5 個方法）
Empathy Map 提示詞› 
以下是我對使用者的觀察或訪談紀錄：

【貼上內容】

請幫我整理成 Empathy Map 的四個象限：
1. Says：使用者實際說了什麼
2. Thinks：使用者可能在想什麼
3. Does：使用者實際做了什麼行為
4. Feels：使用者可能有的情緒或感受

請區分清楚哪些是使用者原話，哪些是你的推論，並標註推論部分。
User Journey Map 提示詞› 
以下是使用者完成一件任務的過程描述：

【貼上內容】

請幫我拆成時間軸上的幾個階段，每個階段請包含：
1. 這個階段使用者在做什麼
2. 使用者當下可能的情緒（正向／中性／負向）
3. 這個階段是否有明顯的痛點

請特別標出情緒最負向的階段。
Persona 提示詞› 
以下是我收集到的使用者訪談或觀察資料：

【貼上內容】

請幫我整理成 1–2 個 Persona，每個包含：
1. 姓名（可用代稱）
2. 背景與生活情境
3. 主要目標
4. 主要痛點
5. 這個 Persona 是根據哪些資料整理出來的

如果資料不足以支撐某個細節，請標記「待補充」，不要自行虛構。
使用者訪談提示詞› 
我想了解以下問題：

【填入問題】

請幫我設計一份不帶有引導性的使用者訪談大綱，包含：
1. 使用者目前的行為
2. 使用情境
3. 遇到的困難
4. 目前的替代方案
5. 對理想解法的期待

請避免直接問「你會不會使用這個功能」這類假設性問題。
觀察法提示詞› 
我想觀察使用者在以下情境中的行為：

【填入情境】

請幫我設計一份觀察清單，包含：
1. 應該觀察哪些具體行為（不是感受或想法）
2. 應該記錄哪些環境或情境細節
3. 哪些行為可能跟使用者「說的」不一致，需要特別留意

請聚焦在可以被實際看到、記錄下來的行為，不要包含需要詢問才能得知的內容。
