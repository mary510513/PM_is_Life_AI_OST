1.3 收斂問題與選擇方向

Prototype demo — 內容排版預覽，尚未套用到正式網站

跟 1.1 / 1.2 的差異：1.1 猜、1.2 驗證，1.3 是從一堆真實但零散的痛點裡，選出一個現在最值得先做的方向。
WHY 為什麼要收斂
  • 1.2 讓你拿到好幾個真實但零散的痛點，不可能同時都做。
  • 如果沒有先收斂，PRD 寫到一半會發現範圍太大、方向不聚焦。
  • 這一步不是要找出「最厲害」的方向，只是要選出「現在最值得先做」的一個。
HOW 可以嘗試的 5 個方法
Impact / Effort Matrix 影響力大、花的力氣小的優先做
值得規劃
（高影響／高力氣）
優先做
（高影響／低力氣）
不要做
（低影響／高力氣）
有空再做
（低影響／低力氣）
影響力 → 花的力氣 →
解法：在店家頁面顯示「預估出餐等待時間」，用店家過去平均出餐時間估算，不需要即時串接店家系統。
為什麼高影響：幾乎每個外送員每天都會遇到等餐，能讓多數人受益。
為什麼低力氣：用既有歷史資料估算即可，不用跟店家系統整合，也不用改動核心派單邏輯。
例：這個解法落在「優先做」象限，適合當作今天的主攻方向。
How Might We 把問題轉成「我們可以怎麼樣⋯」，避免太早鎖定答案
痛點：外送員在等店家出餐時很焦躁
↓ 轉換
HMW 讓等待變得可預期？ HMW 讓等待時間變得有用？ HMW 減少不必要的等待？
例：先轉成幾個開放式問句，而不是直接跳去想「做一個等待進度條」這種單一答案。
Problem Statement 用價值主張句型，把方向收斂成一句話
句型：我們幫助 [目標用戶] 在 [特定場景] 下，透過 [核心功能] 解決 [核心痛點]
↓ 填入內容
我們幫助 外送員，在 等待店家出餐 時， 透過 預估出餐等待時間提示， 解決 不確定能不能先去接下一單的焦慮。
例：四個空格都填上具體內容，才算是真正收斂完成，不是還在講抽象方向。

WHAT 提示詞範例（5 個方法）
Impact / Effort Matrix 提示詞› 
以下是我們目前收集到的幾個問題方向：

【貼上問題清單】

請幫我用 Impact / Effort Matrix 的方式評估每一個：
1. 這個方向的潛在影響力（高／中／低），並說明理由
2. 這個方向需要投入的力氣（高／中／低），並說明理由
3. 綜合以上，這個方向落在「優先做／值得規劃／有空再做／不要做」哪一個象限

請針對每個方向都給出評估，不要只挑一個講。
How Might We 提示詞› 
以下是我們確認過的一個痛點：

【貼上痛點描述】

請幫我把這個痛點轉換成 5 個「How Might We（我們可以怎麼樣⋯）」的開放式問句。
要求：
1. 每個問句都要保留多種可能的解法方向，不要直接暗示某個特定功能。
2. 問句盡量涵蓋不同角度（例如：減少發生、讓使用者更容易應對、改變情境本身）。

請先列出問句，暫時不要幫我選解法。
Problem Statement 提示詞› 
以下是我們目前整理出的多個痛點與觀察：

【貼上內容】

請幫我收斂成一句清楚的價值主張，格式為：
「我們幫助 [目標用戶] 在 [特定場景] 下，透過 [核心功能] 解決 [核心痛點]。」

請只給一句話，如果有多個候選版本，最多列 2 個讓我選，不要超過。
假設地圖提示詞› 
以下是我們目前的問題方向與初步想法：

【貼上內容】

請幫我列出這個方向背後隱含的關鍵假設，並依照「風險高低」與「已知程度」分類：
1. 已知、低風險：我們有把握、資料也支持
2. 未知、高風險：完全沒驗證過，一旦錯了影響很大
3. 未知、中風險：還沒驗證，但影響相對有限

請特別標出「未知、高風險」的假設，這些應該最優先想辦法驗證。
Dot Voting 提示詞› 
我們團隊正在幾個方向之間做選擇：

【貼上方向清單】

在團隊實際投票之前，請先扮演一個中立的第三方，針對每個方向：
1. 列出可能支持這個方向的理由
2. 列出可能反對這個方向的理由
3. 提出一個團隊投票前應該先確認的關鍵問題

請不要幫我們決定選哪個，只是幫我們把利弊看得更清楚。
