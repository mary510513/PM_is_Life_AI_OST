Part 2 · 從需求形成 PRD

2.3 用不同角色檢查 PRD

Prototype demo — 內容排版預覽，尚未套用到正式網站

跟 2.2 的差異：2.2 組裝出一份 PRD 初稿，2.3 是用不同視角把它打破重組，抓出漏洞，最後產出一份真正可以往下走的 PRD v2。
WHY 為什麼要做這一步
  • PRD 初稿是一個人（或一路都用同一個 AI）的視角，容易有盲點看不到。
  • 只用同一個 AI 扮演不同角色還不夠，因為同一個模型可能有自己的系統性盲點，換一個完全不同的 AI 交叉驗證，才能抓到所有角色都沒發現的問題。
  • 收到回饋不代表要全部照做，需要一個機制篩選、決策，PRD 才能真的變得更好，而不是越改越亂。
HOW 3 階段、4 個方法
階段一

角色壓力測試

Role-based Grill 5 個角色，針對假設清單逐條質疑，不是泛泛而談
🧑
外部使用者
這真的解決我的問題嗎？預估錯了怎麼辦？
💳
外部購買者
值得付費／採用嗎？跟其他選擇比優勢在哪？
🛠️
工程師
做得出來嗎？哪個假設錯了會讓方案垮掉？
🎨
設計師
使用者會不會看不懂？流程是否夠直覺？
🧭
內部決策者
值得投入資源嗎？成功指標夠不夠說服人？
例：工程師角色質疑「店家歷史出餐資料從哪來？如果店家從沒紀錄過怎麼辦？」——直接針對假設清單裡的一條發問，不是空泛地說「這個風險要注意」。
階段二

換模型交叉驗證

Cross-Model Validation 同一份 PRD 換一個完全不同的 AI 檢查，抓出所有角色都沒發現的系統性問題
🤖
AI 模型 A
（階段一使用的）
⇄
🧠
AI 模型 B
（換一個不同的）
✓ 共同發現Reach 數字（800人/月）沒有標明資料來源
⚠ 只有 B 發現完全沒考慮店家可能拒絕分享出餐資料
例：階段一用同一個 AI 扮演角色，容易受限於這個模型本身的思考習慣；換一個完全不同的 AI，才能抓到「所有角色都沒發現」的系統性問題。
階段三

校正並產出 PRD v2

Feedback Reconciliation（回饋整理表） 把階段一、二的所有回饋，逐條決定接受／修改／不採用
回饋來源回饋內容決策理由
工程師角色店家歷史出餐資料可能不準確接受真實風險，補進風險清單
換模型驗證店家可能拒絕分享出餐資料接受補一條新假設，標記待驗證
內部決策者建議先做付費功能不採用超出這次 MVP 範圍，記錄但不處理
Definition of Ready（就緒檢查清單） 確認 PRD 已經準備好交給 Part 3 做 Demo
✓
每個 Must-have 功能都有清楚的使用者流程了嗎？
✓
已知的高風險假設，是否都已經有初步回應？
✓
是否已經看過至少一個跟自己角色不同的觀點？
✓
是否已經用第二個 AI 模型交叉檢查過一次？
✓
這份 PRD 是否已經不再包含「待確認」以外的模糊字眼？
✓ 全數通過 → 產出 PRD v2
WHAT 提示詞範例（4 段）
角色壓力測試提示詞› 
以下是我們的 PRD 初稿，以及還沒驗證的假設清單：

【貼上 PRD】
【貼上假設清單】

請分別用以下五種角色檢查，並針對假設清單逐條質疑，不要只是泛泛而談：

1. 外部使用者：這個產品真的解決我的問題嗎？如果預估錯誤會怎樣？
2. 外部購買者：值得採用或付費嗎？跟其他選擇比起來優勢在哪？
3. 工程師：這做得出來嗎？哪一條假設如果是錯的，會讓整個技術方案垮掉？
4. 設計師：使用者會不會看不懂這個流程？有沒有不夠直覺的地方？
5. 內部決策者：這值得投入資源嗎？成功指標夠不夠有說服力？

請針對每個角色，明確指出「哪一條假設」讓他們最擔心，不要給空泛的建議。
換模型交叉驗證提示詞› 
請把以下 PRD 貼給另一個 AI 工具（例如換到 Claude、Gemini 或 ChatGPT，選一個跟你剛剛用的不同）：

【貼上 PRD】

請該 AI 扮演一個對這個專案完全不熟悉的資深產品顧問，直接指出：
1. 這份 PRD 最大的三個風險是什麼？
2. 有沒有明顯被忽略、但很重要的使用者情境？
3. 如果你是決策者，你會卡在哪一點不敢放行？

拿到回覆後，請對照第一個 AI 給的角色回饋，列出：
- 兩邊都提到的共同問題
- 只有這個新 AI 提到、但第一個 AI 沒發現的問題
回饋整理表提示詞› 
以下是我們收到的所有回饋：

【貼上階段一、階段二收到的所有回饋】

請幫我整理成一張表格，欄位為：回饋來源、回饋內容、建議決策（接受／修改／不採用）、理由。

決策原則：
1. 涉及真實風險或明顯漏洞的回饋，傾向接受。
2. 超出這次 MVP 範圍的建議，先標記「不採用，但記錄」。
3. 如果兩個回饋互相矛盾，請列出來讓我自己判斷，不要自動選一邊。
Definition of Ready 提示詞› 
以下是我們修改後的 PRD：

【貼上修改後的 PRD】

請幫我用以下清單檢查這份 PRD 是否已經準備好交給下一階段做 Demo：
1. 每個 Must-have 功能都有清楚的使用者流程了嗎？
2. 已知的高風險假設，是否都已經有初步回應（不用已驗證，但至少知道怎麼驗證）？
3. 是否已經納入至少一個跟原始撰寫者不同的觀點？
4. 這份 PRD 是否已經不再包含「待確認」以外的模糊字眼？

請針對還沒通過的項目，具體說明還缺什麼，不要只回答「通過」或「不通過」。
